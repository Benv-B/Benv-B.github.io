板子不会撒谎

我做了一个面向嵌入式调试的 agent,叫 Yoma。它会烧录、会抓日志、会 gdb、会看原理图和手册,改完代码自己上板验证 —— 而不是改完就说"应该可以了"。

钩子 · 问题

写代码的 agent 很多,碰得到板子的几乎没有

用通用 coding agent 写嵌入式代码,体验是割裂的:它写得很快,但写完那一刻工作才刚开始 —— 编译、烧录、接串口、开 gdb、翻手册查寄存器。这些它一样都碰不到,所以它只能猜:猜引脚接在哪、猜寄存器哪一位、猜时序对不对。猜错了不会报错,板子只是安静地不动。

嵌入式的瓶颈从来不是写代码,是验证。一个碰不到板子的 agent,本质上是一个很贵的自动补全。

这一段换成你自己被"猜"坑过的一次真实经历(哪颗片子、猜错了什么、花了多久才发现),比泛泛地说有力得多。

定位

Yoma 是什么

一个桌面端 agent(目前发 Windows x64 安装包),面向嵌入式调试。一句话:不止是代码编辑,而是根据硬件事实全流程闭环调试。它把嵌入式工程师桌上那几样东西 —— 烧录器、串口、gdb、逻辑分析仪、原理图、数据手册 —— 做成了 agent 原生的工具,而不是让模型去"想象"它们。

开源,MIT。内核派生自 pi,桌面端继承自 opencode —— 站在两个巨人肩膀上,我做的是嵌入式这一层。

差异化功能

它手上有什么

下面这些不是提示词技巧,是 agent 能直接调用的工具 —— 左边就是它在会话里用的名字:

flash烧录
OpenOCD、J-Link、厂商 CLI 都行,agent 自己组命令行。烧完落账,它知道板上此刻跑的是哪一版固件。
log日志采集
串口或 RTT(从 J-Link / OpenOCD 的 TCP 口读),支持长时间采集;可以"等某个关键字出现再往下走",不用人盯着。
gdb调试
OpenOCD、J-Link、QEMU 后端。断点、单步、表达式求值、故障现场分析 —— 它看的是寄存器和栈,不是猜的。
la逻辑分析仪
DSLogic 原生集成,不用装 DSView。采集加 150 个协议解码器(I²C / SPI / UART……),agent 直接问"总线上发生了什么",拿到的是事务级答案:哪个地址被 NACK、哪一帧缺了 STOP。
netlist原理图 / 网表
读 Altium Smart PDF、Altium / OrCAD 网表、KiCad 网表,解出引脚映射和外设连接。"PA9 接的是什么"不用问你,它自己查。
datasheet数据手册检索
在手册库里按芯片搜寄存器和外设说明,带引用。规矩是:寄存器级的结论必须有手册出处,没有出处就不算结论。
examples例程库
从厂商已验证的例程里检索,把例程 seed 进工程当起点。永远从例程起步,不空白写驱动 —— 先跑通绿点,再改一处、验一处。
stm32configSTM32 配置
写一份配置文档,校验、求解时钟树之后直接生成可编译运行的驱动代码。

把这些串起来就是它的工作方式:改代码 → 编译通过 → 烧录 → 拿 log 或 gdb 的板级证据 → 才下结论。证据链断在哪一环,它就停在哪一环,不往下编。

场景 · 走一遍

一个问题从头到尾

以"I²C 温度传感器读不到数据"为例,它会这么走:

  1. 读网表:确认 SDA / SCL 接在哪两个脚、板上有没有上拉。
  2. 查手册:这颗片子 I²C 外设的时钟使能位、GPIO 复用号,每一条带出处。
  3. 从例程起步改代码,编译,烧录。
  4. 接逻辑分析仪抓一把总线:解码出来是对 0x48 写、从机 NACK —— 问题不在代码,在地址。
  5. 回到原理图看 ADDR 脚的接法,改地址,重烧。
  6. 串口 log 里温度值出来了 —— 到这一步它才说"修好了",并把那条 log 附在结论里。
图 · 待补用一次真实运行替换上面这段:会话截图或 30 秒录屏。一个真实的 NACK 比编的故事有说服力十倍 —— 这一节是整篇文章最值钱的位置。
远程调试experimental

板子在工位,代码在研发机

很多团队的现实是:写代码的人和板子不在一个地方。Yoma 为这种情况做了一个实验性的"信箱闭环":两台机器各跑一个 agent,中间只隔一个 git 仓库。

  • 研发端有工程和工具链:读证据、改代码、构建,把固件当附件塞进本轮,用大白话写指令。
  • 工位端只有板子:领指令和附件,自己决定怎么上板,复现观察,把 log、采样数据和结论回填。
  • 多轮往返直到收敛;每一轮都是一次 commit,全程可审计。
  • 要人动手的时候(接电源、换负载)有专门的"等人"状态,agent 不空转。
  • 两端的模型上下文都留在本机,只有指令、附件和证据过网。

这一块还没在真正的两台机器上跑过。措辞要克制 —— 说"在做",别说"已支持"。

取舍

几句实话

  • 没有权限确认。它能烧录、能 gdb、能跑命令,不会弹窗问你 —— 所以只在你信任的本机上用。这是产品决定,不是疏忽。
  • 目前只有 Windows x64 安装包,还没做代码签名,SmartScreen 会拦一次;Release 里有 SHA256 可以核。
  • 烧录 / gdb 依赖你本机装好的 OpenOCD、J-Link 或厂商工具链;手册检索需要自建一个手册服务器。
  • 模型用自己的 key:设置页里配 DeepSeek 或 Kimi 就能跑。
  • 远程调试是实验特性。
上手

三分钟跑起来

装安装包,设置页填 API key,打开一个工程就可以开始。想从源码跑:

git clone https://github.com/yoma-embedded/yoma-pi.git
cd yoma-pi && bun install
bun engines/build.ts    # 网表解析 / STM32 工具
bun dev:desktop
